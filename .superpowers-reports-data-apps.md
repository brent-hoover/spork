## Section 1 — `data:` (commit c11d881)

### What changed
- `src/avspec/model.py`: added `EntityField`, `Relation`, `Entity`, `Data` models;
  `Manifest.data: Data | None = None`; `Module.owns: list[str] = []`;
  `Stack.store: str | None = None` (free-form persistence detail — lives on
  Stack per the task, not on Data).
- `src/avspec/rules/wellformed.py`:
  - `PREFIXES["entity"] = "ENT-"` (and `PREFIXES["app"] = "APP-"`, used from
    commit 2 onward once `Manifest.apps` exists).
  - `_all_ids` includes entity ids — duplicate/prefix checks cover them for free.
  - `dangling_refs` extended: `module.owns` → entity ids, `entity.relations[].to`
    → entity ids, `entity.fields[].ref` (when set) → entity ids, and
    `view.shows` entries starting with `"ENT-"` are parsed as `ENT-x.field` and
    checked against the entity's field list; other `shows` strings stay free-form.
  - New rule `entity_multi_owner` → `ENT_MULTI_OWNER` (error): an entity owned
    by more than one module.
- `src/avspec/rules/completeness.py`: new rule `data_present` →
  - `NO_DATA` (todo) when `manifest.data is None`; explicit `data: {entities: []}`
    is a valid "no persistent data" answer and does NOT fire this.
  - `ENT_NO_FIELDS` (todo) per entity with an empty `fields` list.
  - `ENT_UNOWNED` (todo) per entity owned by no module.
- `src/avspec/findings.py`: `CODE_ORDER` gained `NO_DATA`, `ENT_NO_FIELDS`,
  `ENT_UNOWNED` right after `MOD_NO_RESPONSIBILITY`.
- `examples/linkshort/avspec.yaml`: added `data: { entities: [ENT-link] }`
  (fields code/target_url/created_at), `MOD-data.owns: [ENT-link]`,
  `project.stack.store: sqlite`, and upgraded `VIEW-create.shows` to the
  checked `[ENT-link.target_url, ENT-link.code]` form.
- `feature-work/avspec-0.3-restart/design.md`: new section
  "data and apps — added after the sutra dry run" (data half written here,
  apps half appended in commit 2).
- `adapters/guided-qa/SKILL.md`: added `NO_DATA`, `ENT_NO_FIELDS`,
  `ENT_UNOWNED` / `ENT_MULTI_OWNER` bullets under "Writing answers".

## Section 2 — `apps:` (commit 685fcff)

### What changed
- `src/avspec/model.py`: added `App` model (`id`, `name`, `modules: list[str]`);
  `Manifest.apps: list[App] = []`.
- `src/avspec/rules/wellformed.py`:
  - `_all_ids` now also yields app ids (prefix `APP-`) — duplicate/prefix
    checks cover apps for free.
  - `dangling_refs` extended: `app.modules` → module ids.
  - New rule `module_multi_app` → `MOD_MULTI_APP` (error): a module claimed
    by more than one app.
  - New rule `boundary_cross_app` → `BOUNDARY_CROSS_APP` (error): a module's
    `boundaries.may_import` target lives in a different app than the module
    itself. Only fires when both modules are assigned to some app (uses a
    `_module_apps` helper mapping module id → owning app ids, disjoint-set
    check).
- `src/avspec/rules/completeness.py`: new rule `apps_present` →
  - `NO_APPS` (todo) when modules exist but `manifest.apps` is empty.
  - `MOD_NO_APP` (todo) per module absent from every app, once `apps` is
    non-empty.
- `src/avspec/findings.py`: `CODE_ORDER` gained `NO_APPS`, `MOD_NO_APP`

  `... MOD_NO_RESPONSIBILITY, NO_DATA, ENT_NO_FIELDS, ENT_UNOWNED, NO_APPS,

## Notes / judgment calls
- `Stack.store` was added in the data commit (c11d881) rather than the apps
  commit, since it's thematically about persistence, not deployment topology.
  The task listed it under "Model additions" without pinning it to either
  rule set; this is the one place I made an explicit split call.
- `ENT_MULTI_OWNER`, `MOD_MULTI_APP`, `BOUNDARY_CROSS_APP` are error codes and
  were deliberately NOT added to `CODE_ORDER` — consistent with the existing
  convention where error codes (`DUPLICATE_ID`, `PREFIX_MISMATCH`,
  `DANGLING_REF`, `BOUNDARY_CYCLE`, `CONTRACT_UNPARSEABLE`, `PATH_ESCAPE`)
  aren't in `CODE_ORDER` either — errors already sort first by severity, and
  ties break on `ref`.
- `view.shows` parsing for the `ENT-x.field` checked form splits on the
  first `.` via `str.partition(".")`; a malformed entry (missing dot, or a
  dot but empty field name) is treated as `DANGLING_REF` rather than a
  separate error code, since the task only asked for two named error codes.
